## 先看清楚 WordPress 的硬件底线在哪

WordPress 本身不挑服务器，PHP + MySQL 对 CPU 的要求不高。它真正吃的是内存和磁盘 I/O。

按 WordPress 官方给的技术建议，底线大致是：PHP 8.3 及以上、MySQL 8.0 或 MariaDB 10.6 及以上、启用 HTTPS。低于 PHP 8.1 的环境，主流插件（Elementor、WooCommerce、Yoast SEO 这些）已经明确不再支持，装上去大概率报错。

内存的参考值更实际一些：

- 纯内容站：256MB 内存勉强能跑，但 1GB 更稳
- 带 WooCommerce：官方场景建议 512MB 以上，实际运维中 2GB 起步才不揪心
- 数据库和 PHP-FPM 都会持续占内存，2GB 内存跑 WordPress 不是不能跑，是余量太薄，后台任务一多就容易卡

磁盘方面，SSD 是及格线，NVMe 会明显更快。真正容易把盘撑满的往往不是 WordPress 本体，而是上传的图片、日志文件和本地备份。

## 配置怎么起步：按站点类型对号入座

市面上的经验值基本收敛到这几档，可以照抄：

| 站点类型 | 建议起步配置 | 什么时候该升级 |
| --- | --- | --- |
| 个人博客、单页官网 | 1核1G / 20–40GB SSD | PV 过 3000，或装了重插件后 CPU、内存常年 70% 以上 |
| 内容站、带表单的官网 | 2核2G 或 2核4G / 40–60GB | 后台编辑卡顿、TTFB 超过 600ms |
| WooCommerce 小店 | 2核4G 起，建议 4核8G / 80GB | 高峰下单 CPU、I/O 飙升，结账延迟超过 2 秒 |
| 多站点、多语言站 | 4核8G 以上，拆分数据库和缓存 | 站点数超过 5 个，或单节点延迟不稳 |

一个常被忽略的点：缓存策略比堆硬件管用。内容站开了页面缓存之后，同样一台 2核2G 能扛的并发，可能比没做缓存的一台 4核8G 还多。所以没必要为了"以后可能有流量"提前买大机器。

## WordPress 建站的实际操作流程

不管买云服务器还是虚拟主机，用宝塔部署 WordPress 的流程基本一致：

1. 购买时系统镜像选 Debian 或 Ubuntu，软件选择宝塔面板（虚拟主机则直接选宝塔主机面板）
2. 创建完成后，从控制台复制面板地址、账号密码，浏览器登录
3. 首次进入会提示安装套件，选 LNMP 即可，等编译完成
4. 解析域名，把 www 主机记录指向服务器的公网 IPv4
5. 面板左侧"网站"→"添加站点"→"一键部署"，模板选 WordPress，填入解析好的域名
6. 申请 Let's Encrypt 证书，打开"强制 HTTPS"
7. 访问域名进入 WordPress 安装向导，数据库名、用户名、密码从面板的"数据库"页面复制
8. 填站点标题和管理员账号，装完进后台更新到最新中文版本

有两个坑值得提前说：

**数据库地址别填错。** 在雨云虚拟主机上装 WordPress，程序内的数据库地址要填 `127.0.0.1`，端口填 `3306`，而不是控制台上显示的远程 MySQL 端口。远程连接工具（比如 Navicat）才用控制台那个端口。

**虚拟主机别乱改宝塔设置。** 一些用户反馈在面板里随手绑定域名或修改端口，会导致面板本身访问不了，需要走雨云的"修复主机"功能。升级宝塔版本同样有风险，官方文档的措辞是"不可轻易升级"。
